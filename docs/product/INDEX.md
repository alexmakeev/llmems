# llmems — Product Memory

CEO product-memory. Updated: 2026-06-15.

## Product Definition

**llmems** is a **cache-optimal context generator** for LLM agents.

- The library stands in front of any agent or model and replaces manual context management with
  automatic, efficient memory.
- It does **not** generate final answers — that is the consumer's responsibility.
- It does **not** route models, manage billing, or provide UI.

**Two core pillars:**

1. **Context generation** — memory continuously absorbs new information; before each model call it
   synthesizes an optimal context for the current step. Generation happens INSIDE llmems; the final
   answer is generated by the consumer model OUTSIDE.
2. **Cache efficiency** — stable cache-friendly backbone prefix, incremental append of new facts,
   soft re-indexing at threshold (~30% stale dropped, ~70% retained, single re-index, back on cache).
   Current gap: no explicit `cache_control` hints to provider yet (open plan item).

**Public API (v0.4.0):**
- `remember(turn)` — mutates per-session state (raw tail append, focus vector, dedup mem-load,
  soft rebuild, fire-and-forget indexing)
- `getCurrentContext()` — pure projection to a prompt-block string (stable backbone → loaded mems → raw tail)
- `getCurrentContextParts()` — structured 3-part view exposing stable/dynamic/tail boundary (for cache-hint injection)
- `getLongTermContext()` — long-term-only mode, excludes active raw tail

## Role in Ecosystem

- **Primary consumer:** проприетарная мультиагентная платформа разработки владельца (отдельный продукт, отдельный repo).
- **Moat:** cache-efficient context generation is the competitive differentiator for that application.
- **Backend-agnostic:** plugs as a context-generation layer in front of any code agent or model.
- **Future secondary:** teams embedding LLM agents into their own processes.

## North Star Metric

Cache hit rate (provider prompt cache) on real sessions of the primary consumer application + reduction of repeated context
re-injection. Supporting: tokens saved via cache hits, % tests green on main (target: 100%),
subjective: agent stops "forgetting" on long sessions.
